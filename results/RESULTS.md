# JevTraffic 实验结果

任务：USTBench Traffic Signal Control（CityFlow，杭州 4×4 / 济南 3×4，每 30s 决策一次，3600s 共 120 步）。
指标：ATT 平均通行时间（越低越好）、AWT 平均等待时间、AQL 平均排队长度。完整表格见 `summary.md` / `summary.csv`，每次运行的逐步记录在 `runs/`。

- 训练文件：`hangzhou_real`、`jinan_real`、`jinan_real_2000`
- **留出测试文件**（训练与温度拟合均未见过）：`hangzhou_real_5816`、`jinan_real_2500`
- Jev 实现：开源方案思路（单次前向，读答案位置的选项字母 logits，softmax 得到带概率的类型化答案，不生成文本），未调用任何官方 API。底座 Qwen2.5-7B-Instruct。
- 规则基线跨种子确定性一致（std=0）；LLM 行为单次运行，<1% 的差异应视为噪声。

发现：
- 零样本单次前向的 Jev 读出远差于 MP：与 MP 一致率仅 3–17%，却有 ~0.97 的置信度（严重过度自信）。主因是**位置偏置**（偏向选项 A/ETWT）和直行偏置（左转相位几乎不选）。
- 选项置换去偏（perm2/perm4）没有改善；置信度门控（τ=0.6 回退 MP）因过度自信几乎不触发。
- 0.5B 模型全面更差，门控后 100% 回退（等同 MP）。
- 生成式 CoT 接近 MP，但每决策约 2s，比单次前向慢 ~35 倍。

## 2. 微调（三阶段）

数据：在训练文件上运行 MP（ε∈{0,0.1,0.25,0.5} 随机扰动 × 3 种子），记录 56,160 个（结构化状态、MP 动作、4 相位 30s 反事实 rollout 代价）样本；验证集 ε=0.1 种子 100；测试集为两个留出文件。LoRA r=16，只在答案字母（A–D 的受限 softmax）上算损失，与推理读出一致；每样本随机打乱选项顺序以消除位置偏置。

| 阶段 | 训练 | 设置 |
|---|---|---|
| 1 蒸馏 MP | `ckpt/distill-typed` | CE 硬标签 = MP 动作，0.5 epoch，4×A800 ~28 分钟 |
| 2a 回报加权 | `ckpt/reward-soft` | 在蒸馏模型上，soft target = softmax(−Δcost/(0.25·span))，0.5 epoch |
| 2b DPO | `ckpt/reward-dpo` | 在蒸馏模型上，(rollout 最优, 更差) 相位对，β=0.5，参考模型 = 蒸馏模型 |
| 3 温度校准 | `calib.json` | 在 1,500 条验证决策上网格搜索单一温度 T（最小 NLL） |

## 3. 结论

1. **蒸馏有效且泛化**：Jev 式单次前向读出经 LoRA 蒸馏后，在两个留出文件上与 MP 一致率 ~90%，在线 ATT 与 MP 持平（−0.3%），速度 ~56 ms/决策，比生成式 CoT 快 ~35 倍且更好。
2. **仿真回报提升空间很小**：以 30s 短期等待车辆数为回报的 rollout-greedy 本身只比 MP 好 1.2%（且在济南两个文件上不占优），所以阶段 2 的上限就在这个量级。DPO+门控取得最好的平均 −0.6%，回报加权没有收益；两者都抬高了 AWT（例如 hz_5816：蒸馏 53.6 → 回报加权 98.2），说明短期回报与 ATT/AWT 并不完全对齐。
3. **校准的作用在阶段 2 才显现**：交叉熵蒸馏的模型天然近似校准（T≈0.95）；回报加权的 soft target 让模型欠自信（T=0.52），DPO 让模型严重过度自信（T=3.86，ECE 0.18→0.07）。单一温度即可把 ECE 压到 0.02–0.07，使 τ=0.6 门控变得可用。
4. **门控收益小但稳定**：在各模型上回退 7–15% 的低置信决策给 MP，平均额外改善 0–0.3%。

## 4. 局限与下一步

- LLM 运行为单次（仿真确定性，但 ATT 差 <1% 不应视为显著）；留出文件只有两个。
- 阶段 2 回报仅看 30s 短期等待；可尝试更长 horizon、多步 rollout 或直接以 ATT 增量为回报，并加入 AWT 约束。
- 可在线迭代（DAgger/在线 DPO：用当前策略采样状态再打标签），以及在更多城市路网（如纽约 28×7）检验泛化。

## 附注：USTBench 相位映射

USTBench 的 `_selection_to_signal_code` 使用 `['ETWT','ELWL','NTST','NLSL']`，而路网定义的相位顺序是 `0=ETWT, 1=NTST, 2=ELWL, 3=NLSL`，导致其 LLM 选择被映射到错误的相位。本实现使用路网顺序。这可能是 USTBench 报告的 Qwen2.5-7B 成绩（ATT 820.28）明显差于本文生成式 CoT（~320）的原因之一。
